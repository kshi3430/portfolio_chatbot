## [CapTeam / 문제와 해결] 학생 분석 결과의 랜덤성과 과대평가 문제

- **문제**: LLM이 학생의 기술 수준을 일관성 없이 평가하거나, 단순 튜토리얼 수준의 구현 경험도 과대평가하는 문제가 있었습니다.
- **해결**: `temperature`를 0으로 설정하고 후처리 보정 로직을 추가했습니다. 경험 텍스트에서 '단순 구현'과 '실제 수행' 키워드 빈도를 추출해 프롬프트에 전달하고 실제 수행 근거가 충분히 확인될 때만 보통 이상을 부여했으며, 최종 등급이 보통이면 기술 점수를 최대 7점, 낮음이면 최대 4점으로 제한했습니다.
- **결과**: 학생 분석 결과의 일관성이 높아졌고, 기술 수준이 과대평가되는 문제가 줄어들었습니다.
- **기술**: LangChain, Python, Prompt Engineering

## [CapTeam / 문제와 해결] 팀 수정 반복 루프 문제

- **문제**: 팀원 선호 미반영까지 오류로 간주되어 최대 횟수까지 팀 수정이 반복되면서 응답 시간과 비용이 증가했습니다.
- **해결**: 학생 누락·중복 및 인원 제한 위반만 필수 오류로 정의하고, 팀원 선호 미반영은 참고 경고로 분리했습니다. 반복 횟수와 이전 수정 내역을 기록해 동일 패턴 반복을 막고, 최대 횟수 초과 시 규칙 기반(Rule-based) 알고리즘으로 자동 fallback하도록 설계했습니다.
- **결과**: 불필요한 반복이 줄어들고, 팀 매칭 워크플로의 안정성이 개선되었습니다.
- **기술**: LangGraph, Python, Rule-based Algorithm

## [CapTeam / 문제와 해결] 컨텍스트 길이와 성능 문제

- **문제**: 모든 팀의 매칭 사유와 강약점을 단일 LLM 요청에서 생성하면서 컨텍스트 길이가 길어지고 응답 시간이 크게 증가했습니다.
- **해결**: 팀 단위로 결과 생성을 분리하고 독립 작업을 병렬 처리 구조로 개편했습니다. Rate Limit과 timeout을 고려해 Worker 3개, Batch 6개로 제한해 안정성을 확보했습니다.
- **결과**: 전체 소요 시간이 514.67초에서 179.44초로 335.23초 단축되어 약 2.87배 속도가 향상되었습니다.
- **기술**: Python, Parallel Processing, LangChain
